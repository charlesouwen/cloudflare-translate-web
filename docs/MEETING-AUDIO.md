# Teams 会议音频指南

本指南面向 Windows 上的 Chrome/Edge 与 Teams。目标是把会议对方的声音送入网页“对方”通道，把所选我方 `audioinput`（通常为物理麦克风）送入网页“我方”通道，并将翻译后的 TTS 作为 Teams 麦克风输入。

## 1. 能力边界

- 网页只能读取用户主动授权的 `audioinput` 和 `getDisplayMedia()` 返回的共享音轨。浏览器会列出物理与虚拟输入，网页不能可靠判定其设备类型。
- 浏览器每次开始共享都必须显示系统选择面板；网页不能预选或永久保存某个标签页、窗口、应用或扬声器权限。
- 普通网页不能把 `audiooutput` 扬声器直接当作输入，也不能注册成 Teams 麦克风。
- “共享窗口”不保证返回该进程的音频，“共享屏幕区域”也不能只截取区域对应的声音。实际能力取决于 Windows、浏览器和被选应用。
- 网页 TTS 要进入 Teams，必须借助 VB-CABLE、VoiceMeeter 或其他系统级虚拟音频设备。

## 2. 推荐拓扑

Teams Web 的推荐设置：

```text
Teams 标签页音频 ----------------------> 网页：对方通道
所选我方输入（通常为物理麦克风） ------> 网页：我方通道
网页译音（只播我方译文） -> CABLE Input -> CABLE Output -> Teams 麦克风
Teams 扬声器 --------------------------> 物理耳机
```

在 VB-CABLE 中，`CABLE Input` 是 Windows 播放端，`CABLE Output` 是应用可选择的录音端。名称看起来相反，但这正是它们的信号方向。

一条 VB-CABLE 只能在这套拓扑中承担 TTS 出站，不能同时用它把 Teams 远端声音回采给网页。否则远端输入和网页译音会进入同一总线，导致无远端声、错误识别或回声循环。Teams Web 应优先共享 Teams 标签页音轨；必须处理桌面版时，使用整屏系统音频、Stereo Mix，或用 VoiceMeeter 为远端回采和 TTS 出站建立两条独立总线。

必须使用耳机。若 Teams 扬声器也输出到 Cable，对方声音会重新进入 Teams；若网页 TTS 输出到物理扬声器，麦克风可能再次收录译音。

## 3. VB-CABLE 设置

1. 从 VB-Audio 官方渠道安装 VB-CABLE，按安装程序要求重启 Windows。
2. 打开 Windows“设置 -> 系统 -> 声音”，确认输出设备中存在 `CABLE Input`，输入设备中存在 `CABLE Output`。
3. 保留物理耳机为 Windows/Teams 的正常播放设备，不要把 Cable 设为所有应用的默认扬声器。
4. 在翻译网页的“译音输出设备”中选择 `CABLE Input`。
5. 在 Teams“设置 -> 设备”中，把麦克风设为 `CABLE Output`，把扬声器设为物理耳机。
6. 在网页播放一次输出测试音，并观察 Teams 麦克风电平。测试结束后应没有持续电平或回声。

浏览器只有在获得媒体设备权限后才可能显示完整设备名称。找不到设备时，先允许麦克风，再刷新设备列表；仍找不到则重启浏览器。

## 4. Teams Web 操作

1. 使用 Chrome 或 Edge 打开 Teams Web，并加入会议前的设备检查页面。
2. 另一个标签页打开翻译网页，选择“会议双通道”。
3. 在网页选择我方 `audioinput`（通常为物理麦克风），选择 `CABLE Input` 作为译音输出。
4. 点击开始。浏览器弹出共享面板时选择正在运行 Teams 的标签页，并明确开启“共享标签页音频”。
5. 页面只有一个全局活动状态，不显示两个独立通道指示器。让对方先说一句，再对所选我方输入说一句；在消息时间线中确认前者标为对方、后者标为我方，且两条译文方向正确。
6. 在 Teams 中确认麦克风是 `CABLE Output`，扬声器是物理耳机。
7. 让对方说一句目标语言：网页应显示并翻译给我，但不向 Cable 播放。
8. 对所选我方输入说一句中文：网页应识别、翻译并将译文 TTS 送到 Cable，Teams 麦克风电平应随译音变化。

会议模式只自动播报我方译文。关闭自动播报后，网页仍显示译文，但不会向 Teams 发送声音。

## 5. Teams 桌面版

浏览器对独立桌面窗口音频的支持不一致。选择 Teams 桌面窗口后即使画面共享成功，也可能没有音轨。可按以下顺序尝试：

1. Windows + Chrome/Edge 支持时，选择“整个屏幕”并开启“共享系统音频”。这可能同时捕获通知和其他应用声音。
2. 启用 Windows `Stereo Mix`，将它作为网页可见的回采输入。并非所有声卡驱动都提供该设备。
3. 使用 VoiceMeeter 把 Teams 播放、物理耳机监听、网页采集和虚拟麦克风拆成独立总线。
4. 若组织策略禁止系统音频共享或安装虚拟驱动，只能使用所选输入/扬声器进行声学回采，质量和回声隔离无法保证。

网页无法提供精确的单进程 WASAPI 回采。要求稳定捕获某个桌面应用且隔离其他声音时，需要原生桌面程序或经过管理员批准的音频路由软件。

## 6. VoiceMeeter 场景

当需要同时监听原声、只把译音送入 Teams，或同时需要远端回采和 TTS 出站时，应使用 VoiceMeeter 或两组相互隔离的虚拟总线：

- 将 Teams 播放送到一个虚拟输入，并同时路由到物理耳机与网页回采总线。
- 将网页 TTS 输出送到另一条虚拟总线，该总线只连接 Teams 麦克风。
- 将所选我方输入（通常为物理麦克风）直接交给网页，不要同时直通 Teams，否则对方会同时听到中文原声和译音。
- 给每条总线清晰命名，并逐条静音测试；不要仅凭系统设备名称猜测路由。

具体按钮名称会随 VoiceMeeter 版本和语言变化，本项目不自动修改该软件的配置。

## 7. 标签页、窗口与整屏的区别

| 共享类型 | 常见音频能力 | 适用场景 | 主要风险 |
|:---|:---|:---|:---|
| 浏览器标签页 | Chrome/Edge 通常最稳定，可明确共享标签页音频 | Teams Web、网页视频、在线课程 | 只能捕获所选标签页；标签页关闭即结束 |
| 应用窗口 | 音轨支持依浏览器与应用而异 | 可验证支持音频的桌面窗口 | 画面成功但音轨为空 |
| 整个屏幕 | Windows/Chromium 可能提供系统音频 | Teams 桌面版或多应用混合 | 通知、音乐及其他应用声音也会被上传识别 |

页面必须以浏览器实际返回的音轨为准。共享弹窗中的表面名称不能证明音频捕获成功。

如果共享表面没有音轨，网页可能尝试名称匹配的系统回采 `audioinput`。为阻止 TTS 自回采，它可能拒绝与译音输出属于同组的 Cable 设备。自动匹配不是音频路由器：失败时应改用 Teams Web 标签页共享，或在 VoiceMeeter 中准备一条与 TTS 出站隔离的远端回采总线。

## 8. 输出设备测试

正式入会前使用 Teams 测试通话或第二个账号验证：

1. 网页选择 `CABLE Input`，播放短句。
2. Teams 选择 `CABLE Output`，确认麦克风电平变化且远端能听清。
3. 网页关闭自动播报，确认 Teams 电平归零。
4. 播放对方声音，确认它只从物理耳机出现，不进入 Cable。
5. 同时说话测试时，留意 TTS 播放期间存在短暂的采集保护窗口。这是防止回灌的半双工取舍。

若浏览器不支持 `HTMLMediaElement.setSinkId()`，网页无法可靠指定非默认输出设备。此时不要继续使用浏览器语音回退向会议发送译音，应改用支持的 Chrome/Edge 或在系统混音器中为浏览器固定输出。

## 9. 故障排查

**共享成功但提示无音轨**

- 重新开始并选择浏览器标签页，确认勾选“共享标签页音频”。
- 播放一段有声内容后再观察输入电平。
- Teams 桌面窗口仍无音轨时改用整屏系统音频、Stereo Mix 或 VoiceMeeter。
- 若页面拒绝自动回采，检查候选设备是否就是 TTS 出站使用的 `CABLE Output`；不要强行复用该总线。

**对方听不到译音**

- 网页输出应为 `CABLE Input`，Teams 麦克风应为 `CABLE Output`。
- 检查网页自动播报是否开启，以及会议模式是否把当前消息判定为我方。
- 检查浏览器输出设备权限和 Windows 音量混合器，不要只检查 Teams 音量。

**出现回声或重复翻译**

- Teams 扬声器改为物理耳机，不能使用 `CABLE Input`。
- 关闭 Windows 的“侦听此设备”，除非已明确需要并验证其路由。
- 确认所选我方输入是预期设备；使用物理麦克风时不要贴近外放扬声器。
- 停止后重新启动同传，清除旧共享流和 TTS 队列。

**设备在运行中消失**

- 停止同传后重新插入设备并刷新设备列表。
- 蓝牙耳机切换通话配置时设备 ID 可能改变，需要重新选择。
- 虚拟驱动升级或 Windows 重启后，浏览器保存的设备 ID 可能失效。

**识别出未说过的点赞、关注或字幕文本**

- 确认使用“对话”而不是“音乐”内容模式；会议双通道会固定使用对话模式。
- 检查共享音频中是否实际包含视频片尾、通知或其他标签页声音。
- 在静音环境复现并记录时间、来源模式、语言和浏览器版本，便于结合 Worker 日志定位。

## 10. 隐私与会前检查

共享整屏系统音频可能把通知、其他会议、媒体和私密应用声音发送到 Cloudflare/所选语音服务。录音、转写或把音频转交第三方前，应取得组织与参会者许可，并遵守所在地区法律与公司的会议政策。

会前逐项确认：

- 使用 Chrome/Edge 稳定版和 HTTPS 页面。
- 物理耳机、所选我方 `audioinput` 和虚拟音频设备均已连接。
- Teams 扬声器为物理耳机，Teams 麦克风为虚拟录音端。
- 网页我方输入通常为物理麦克风，译音输出为独立虚拟播放端；该出站总线未被复用作远端回采。
- 共享面板选中了正确来源并明确开启音频。
- 双方语言与方向正确，会议模式只播我方译文。
- 已测试自动播报关闭、设备拔插、停止共享和紧急静音。
- 参会者已知悉转写/翻译链路，敏感通知和无关应用已关闭。
